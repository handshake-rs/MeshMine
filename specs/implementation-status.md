## Architecture and operational status

- The Rust crates expose protocol components and verified state boundaries. `meshmine-node` now runs a persistent authenticated QUIC request/response service and a static-profile exact-share ingress path in addition to CPU mining, local-parent verification, and bounded operator-driven receipt and settlement-member workflows, but it is not a complete production role daemon. Before dispatch, every command is checked against its own option schema: unknown arguments, missing or option-shaped values, and duplicate non-repeatable options fail; only assembly `--signature` inputs are repeatable.
- `meshmine-node research-mine-once` implements a separate one-block stock-hsd regtest path under an explicit research-only acknowledgement and `--stock-regtest-compat`. It fixes `bits=0x207fffff`, `p=q=1,d=0`, binds an absolute canonical CLI by path/length/digest, attests the network and exact regtest genesis initially and immediately before submission, JSON-quotes submission bytes, bounds the nonce/capture scan and RPC I/O, uses a bounded CLI process group on Unix, and exactly reconstructs immutable schema-v3 state on restart. A terminal replay is historical and makes no hsd query, while the separate CLI invocations retain endpoint-configuration TOCTOU. The path does not satisfy the production nonzero-blind-band, MPC, daemon, endpoint-identity, or deployment gates. See `../bins/meshmine-node/RESEARCH-MINE-ONCE.md`.
- A bounded JavaScript artifact verifier independently implements the frozen snapshot, plan, nested TemplateCore/body decoders, object/signature domains, roster certificates, payout selection transcript, candidate linkage, and relevant HNS checks without importing Rust code or node state. Cross-language tests give it correctly signed artifacts, then re-sign semantic substitutions with valid keys and require rejection. The all-object vector generator separately fixes bytes and IDs for all 14 Core objects. This is local implementation diversity, not independent organizational maintenance, a second overlay node, or an external audit; the payout verifier starts at the certified snapshot rather than independently deriving it from receipts. See `independent-audit.md`.
- A fresh RustSec scan of all 165 locked Rust dependencies found no vulnerability advisory and one allowed unmaintained warning (`instant 0.1.13`, pulled by the latest `reed-solomon-erasure 6.0.0`). The fail-closed npm audit found only the exact unpatched `bsock` advisory already allowlisted for isolated, loopback-only oracle test subprocesses. That narrow test exception does not approve the separate long-running hsd deployment; its production audit records the advisory as an operator release blocker pending a reviewed upstream/vendor disposition.
- The distributed mask adapter verifies allowlisted source, circuit, bytecode, schedule, MASCOT executable, and runtime-library identities before importing a strict 824-byte local output. It checks the exact public parent/profile/hash fields, stores only that member's signed opening share in its own durable store, and releases a signed setup commitment only after persistence. Public assembly requires every canonical member contribution and never accepts share bytes. The reviewed `16/8/3/2` ARM64 fixture ran MP-SPDZ MASCOT/Tinier and the Rust conformance tool reconstructed the committed mask from two parties. The conformance tool's central share read is test-only; no production runner, mask-opening gossip, setup-certificate daemon workflow, or independent audit exists. See `../mpc/mp-spdz/README.md`.
- Native QUIC transport is implemented with pinned server TLS, mutual Ed25519 challenge authentication, bounded per-message streams, signed gossip, request/response quotas, durable identities, and restart-tested redb responses. Synchronous gossip and response callbacks execute through separately reserved bounded fast-path, accounting, availability, and settlement blocking-worker gates, leaving the Tokio runtime responsive; live forwarding queues and per-peer QUIC permits use the same lane isolation, replay sends one object at a time without holding metadata or outbox locks over network I/O, and post-send acknowledgment re-resolves the current locator after compaction. Peer-and-generation-bound ingress tokens prevent an expired callback from completing a replacement validation. Pending duplicates reject, while an exact validly transport-signed retry of a completed object is acknowledged without invoking application admission again. `overlay-serve --peer-config` adds at most 64 bounded static peers, one to eight TLS pins for operator-managed certificate overlap, an exact authenticated transport-key pin, exponential reconnect supervision, keepalive, source-suppressed concurrent forwarding, and bounded durable sender-side catch-up. A compact per-peer acknowledgment bitmap, rotating cursor, bounded periodic passes, authoritative-payload loading, and startup repair heal disconnection, live-queue pressure, and source restart with at-least-once delivery; fair retry prevents one rejected object from starving later records. Exact-wrapper publication intents recover the crash gap between authoritative admission and locator publication without conflating wrappers sharing an unsigned object ID. A canonical per-topic-group bitmap performs legacy migration incrementally once, preventing a later restart from blindly republishing already migrated history. Parent migration and intent recovery require a separate accepted-parent marker, so journaled losing siblings cannot enter the outbox. HNS reorg recovery atomically marks and rewinds the accepted orphan suffix; obsolete parent locators and shares in reorg-closed sessions are skipped by intent recovery, migration, live forwarding, source settlement, and replay without setting a peer ACK. A configured peer that missed the orphan therefore receives the same-sequence canonical replacement before its successor. The supervisor atomically retires a contiguous prefix settled for every configured peer or locally tombstoned by that canonical reorg, rebases retained locators and real ACKs, suppresses live resurrection of retired wrappers, and records cumulative generation/retirement evidence; tombstoned prefixes retire promptly, normal passes batch 1,024 objects, and high-water passes accept any settled prefix. Malformed or irreducibly exhausted delivery state stops the service fail-closed. Wrong certificates/keys never receive objects, and tests cover reconnect, offline/queue-pressure replay, every publication crash phase, wrapper concurrency, incremental migration, atomic repeated compaction, source suppression, contextual-topic dependency order, malformed state, callback cancellation, stale validation tokens, completed retries, concurrent parent admission, dependency-safe reorg replacement, and fatal publication failure. Schema-v3 observability exposes bounded exact durable topic/capacity/source/intent/migration/compaction, separate local tombstone counts, and per-peer settled/pending evidence. This is not peer discovery, remote inventory reconciliation, or exactly-once delivery. Peer removal changes the local retirement quorum, and newly enrolled peers cannot recover already retired history without a separate import/inventory workflow or a future bounded parent checkpoint; the active outbox can still fail-stop when no ACK-or-tombstone prefix exists or admission outruns the periodic pass. Body/shard payloads remain request/response only, and automatic rotation/revocation plus durable retry/rejection and live connection-health metrics remain absent. The standalone daemon admits self-contained operator records and, only when explicitly configured with a static settlement roster plus local `hsd`, threshold-signed sequence-linked parent certificates. With explicit mask and availability rosters plus pre-imported canonical context, it also performs exact share linkage, signature/certificate, durable first-observation schedule, capture-target, HNS proof, tip-keyed local-parent, DAG, and durable `work_key` validation before acknowledgment. Context import independently checks the candidate body through running `hsd`'s no-PoW contextual `verifyblock` path; its MaskSession journal write and per-network inventory-generation increment are one guarded transaction conditioned on the parent orphan marker, exact-block MMDB tombstone, session reorg marker, and closure row all being absent. Disconnect preparation and orphan-head rewind both snapshot that generation before scanning sessions and exact-CAS it at commit, so a session-first race forces a rescan and an event-first race rejects the session write. With an explicit receipt roster, threshold-certified receipt batches must form an append-only chain backed by exact local share/work evidence, and settlement-certified session closes must cover the complete chain. The one-shot `committee-key-init`, `receipt-propose`, `receipt-sign`, and `receipt-assemble` path now composes static receipt production without adding a wire object: it rebuilds bounded unsigned batches from locally revalidated active shares, makes each eligible member durably reserve one roster/session/sequence before signing, verifies and assembles a threshold, persists the exact certified wrapper, and closes the admission-to-outbox crash gap before exposing an atomic output artifact. Conflicting valid proposals, outsider keys, exact retries, restart, and interrupted publication are tested. This remains an operator-mediated workflow rather than an automatic proposal-round or partial-signature service. With a strict bounded static payout profile, snapshot recovery replays `SnapshotAccumulator` from complete verified receipt/close/share/bucket evidence and permits only the exact work-only prefix of one linked session lane; signed window, anchor, bucket, and service substitutions fail. Plan gossip must use the exact configured delay, count, research beacon, deterministic selection, and locally canonical HNS entropy. The operator-driven `payout-snapshot-propose`, `payout-plan-propose`, `settlement-sign`, and `settlement-assemble` path independently repeats those checks, durably prevents snapshot ambiguity and same-entropy-branch plan ambiguity, and publishes assembled threshold wrappers crash-safely. The bounded HNS controller decodes canonical blocks through running `hsd` and recognizes only exact commitment-and-output payments of the current plan. A live Disconnect commits the raw event, exact-block MMDB tombstone, earliest parent/session markers and closure rows, parent-head rewind, and exact canonical-sequence (`MMPC`) deletions in one conditional transaction; a losing marker CAS retries the complete transition. Startup first validates the complete ordered raw event chain without writes, aggregates Disconnects by height/hash with the earliest sequence, then scans parent and MaskSession evidence once per complete CAS attempt without normalizing payout evidence. `overlay-serve` reconciles before listening and supervises periodic passes with fail-closed oracle/partial handling. Dynamic roster/context distribution, automatic receipt/settlement rounds and signature transport, session-close/mask-opening production, durable daemon service-credit evidence, multi-lane snapshot ordering, and a production threshold beacon remain uncomposed. Public peer discovery, a complete certificate lifecycle, WAN/eclipse evidence, and independent operation are absent. See `native-transport.md`, `receipt-role.md`, and `settlement-role.md`.
- Receipt and gateway boundaries independently derive `q` and `T_capture` from HNS `bits` and reject inconsistent committee/configuration values. Receipt admission also requires its local observation time to fall inside the certified submission schedule.
- The gateway-to-Core protocol boundary is explicit rather than an `AssignmentV2` relaxation. `GatewayAssignmentV1` signs the HandyStratum `prefix4 || ExtraNonce2[4] || zero16` range plus exact context, identities, targets, sequence, nTime, nonce range, and observation policy. Operator-signed context manifests, gateway-signed capture envelopes/transitions/drains, and Core-signed terminal capture/drain receipts are canonical domain-separated objects. `ShareV2.local_telemetry_hash` commits to the envelope, Core or bounded delegated gateway time is selected by the signed policy, per-assignment sequences are gap-free and drain-fenced, and one transaction commits accepted evidence/cursor/work/share; rejected, grace, and duplicate outcomes commit evidence/cursor but are structurally unable to name a credited share. The unified operator composes the private continuous Unix-domain transport with Linux peer credentials, pinned mutual Ed25519 authentication, exact signed assignment bundles, automatic exact Core-side `ShareV2` construction, bounded durable pending-envelope accounting, signed terminal receipt delivery, signed drain/transition orchestration, bounded authenticated native-`hsrd` parent qualification with current-tip enforcement for served jobs and no runtime HSD process, and the complete local supervisor/dashboard/fallback path. Production gateway eligibility remains false because hsrd authority readiness, compiled fault drills, and physical hardware qualification are still absent. See `gateway-core-handoff.md`, `docs/core-link.md`, `asic-profiles.md`, and `OPEN-QUESTIONS.md`.
- Local `hsd` parent verification is mandatory through `ParentChainOracle`. The bounded `hsd-cli getblockheader` adapter rejects side-chain entries and exact hash/height/nTime/chainwork mismatches. Every non-research CLI consumer requires one absolute canonical regular executable; Unix descriptor traversal rejects symlink or unsafe writable components and unowned/group/world-writable leaves, binds its path/device/inode/owner/mode/size/timestamps/digest, and re-attests immediately before spawning the reopened inode; the optional static-profile daemon parent-ingress path composes it with threshold and durable chain checks. Body/payment adapters separately require an absolute canonical effective-user/root-owned, non-group/world-writable `hsd` source directory beneath no non-sticky group/world-writable ancestor; a non-writable ancestor may have another owner. They re-attest and pass the exact directory descriptor immediately before adapter spawn. Only that directory identity is pinned: the Node launcher imports mutable descendants without a full source-tree content commitment, and the Node runtime is not artifact-bound, so those remain external deployment controls. Same-user/root tree mutation remains a deployment trust gap. A parent certificate is journaled first as immutable audit evidence, while its accepted-parent marker, head, and versioned network/sequence/object canonical binding commit atomically. Parent admission also conditions the exact `(network, height, block_hash)` MMDB tombstone absent, so a certificate validated before a competing Disconnect cannot resurrect stale canonical state. A CAS-guarded page/byte/work-bounded migration follows only the accepted head's predecessor chain and validates a contiguous sequence-zero-to-head index; losing siblings cannot enter it. Reorg rewinds exact-delete the orphan suffix bindings, and same-sequence replacement installs the new binding atomically. Recovery repairs legacy acceptance markers only along the bounded verified head chain, and publication/migration ignore unmarked candidates, so a concurrent losing sibling remains evidence without becoming authoritative gossip. This index is foundational rather than a completed lifetime-bounded design: current head recovery and reorg planning still walk the certificate chain, and reversible checkpoints plus a resumable deep-reorg fence remain open. The exact MMDB tombstone is an admission-race fence, not that still-open deep-reorg repair fence. Parent cache keys include the current local tip and payout entropy is never persistently cached. The supervised HNS controller rechecks canonical hashes and bodies before service and on every bounded interval; the dynamic-roster lifecycle remains deployment work.
- Durable redb storage covers the Core record categories and the gateway/payout extension records through immutable journal namespaces. On Unix, every database-path ancestor is opened and retained through descriptor-relative `openat` with `O_NOFOLLOW`; symlink and group/world-writable non-sticky ancestors fail, sticky shared directories remain usable, and ancestor plus leaf identities are rechecked before the private regular leaf is handed to redb. This traversal does not defeat same-effective-user/root pre-start substitution or durable-state rollback. Audit tools can request a bounded deterministic inventory of all 26 categories and malformed keys fail closed. Service share recovery scans a capped active index, point-loads and revalidates exact share/work/observation evidence, and reconstructs only open DAGs. Share, work-key, observation, and active-row writes commit atomically under the same session-open precondition; gateway evidence and its Core disposition now join the accepted share/work transaction. Open receipt recovery likewise scans capped per-session heads and point-walks bounded immutable predecessor chains. Normal closure markers are bound to one immutable close ID, reorg markers are bound to retained events, and CAS-guarded page/byte/work-bounded share/receipt migrations refuse service until validation proves their evidence and caps. Only post-atomic normal-first state is trusted: the normal-close proof (`MMNP`) namespace is v4 with the `MMN4` encoding, the active-share migration marker is `MMA4`, and the ordered normal-closed-session-index migration is v5 (`MMCI`/`MMC5`). Payout recovery now has a canonical source-fenced checkpoint and atomic monotonic `MMCH` head with constant-lookup loading, but payout-enabled startup still calls historical receipt recovery because source-head advancement and bounded migration/cutover are not composed. Snapshot, plan, canonical-event, observability, and parts of parent recovery therefore remain lifetime-sized under fixed ceilings. Live Disconnect effects remain indivisible, and startup repair validates retained raw history before writing. Signing guards, exact-wrapper intents, gossip recovery/compaction, and the storage trait's same-view multi-condition/multi-journal transactions remain as previously described. This tranche does not close the lifetime-bounded parent-repair/deep-reorg fence or the payout checkpoint's online source/migration cutover; all external production gates remain open.
- Canonical overlay reorg state is composed into the supervised standalone service: it invalidates orphaned parent certificates and entropy plans, closes affected sessions, rolls exact plan payment back, recomputes the current payable sequence, retains share/body evidence, and stops serving when it cannot prove complete reconciliation within its configured bounds.
- `overlay-observe` exports a deterministic schema-v3 JSON snapshot under bounded journal and delivery-metadata scan limits. `overlay-serve --observability-listen` serves that exact schema from an optional loopback-only, GET-only, header/output/time-bounded HTTP endpoint; snapshot work runs outside the QUIC async runtime and listener failure is supervised. The exporter checks object IDs and exact share/work/receipt, session, availability, payout-winner, reorg, gossip-intent/migration/compaction/locator/index/source, local tombstone, and peer-ACK linkages before reporting network-scoped work/template/body/payout/telemetry distributions plus durable delivery capacity/backlog and recovery state. Every §21.2 metric is labeled exact, proxy, raw-only, or unavailable; absent WAN, live-connection, MPC-wire, and physical-ASIC observations are never emitted as zero. This is a local evidence surface, not a public time-series service or explorer UI. See `observability.md`.
- Clock bounds are implemented and the research deployment profile is published in `regtest-profile.md`; per-role assumptions are explicit in `research-role-profile.md`.
- Three finite TLA+ models pass exhaustive TLC exploration. They are useful safety evidence, not theorem-level MPC assurance.

## Performance evidence

On the local aarch64 development host, release builds measured:

- fully signed share validation, including independent capture-profile derivation: 493.943 shares/s/core (target: at least 100);
- 4 MiB body reconstruction: 36.754 ms (target: under 1,000 ms);
- deterministic 100,000-bucket payout verification: 70.659 ms (target: under 100 ms).

These are reproducible engineering observations, not guarantees for other hardware. See `performance.md`.

## Gates that remain externally unresolved

A production-ready label remains prohibited until all of these are supplied:

1. an audited malicious-secure MPC/VSS backend with a stated theorem-level corruption, fairness/output-delivery, and synchrony model;
2. independent review and freeze of the object graph, wire choices, committee sortition, and eligibility authority;
3. published committee parameters that actually meet security/liveness bounds using measured HNS concentration and failure-domain data;
4. physical HS3/Goldshell target, maskHash, share-delivery, failover, and job-switch evidence;
5. a genuine public multi-operator overlay with independent role providers and incident transcripts;
6. at least two organizations operating each critical role;
7. complete production role-daemon qualification, including compiled crash/disk/network fault drills for the live-parent and unified operator path, remote peer inventory reconciliation or equivalent enrollment/retention proof beyond local compaction ACKs, peer discovery and certificate lifecycle, public metrics/explorer operations UI, physical ASIC evidence, and incident response procedures;
8. external maintenance/reproduction of the local implementation-diverse payout/body audit tooling and HNS vectors.

No Boolean configuration flag or local test substitutes for these external facts.
